# Superset JavaScript → TypeScript 迁移

仅明确要求迁移指定 JS/JSX 功能时使用；遵循仓库 `AGENTS.md` 和通用最小实现规则，保持运行行为与公开接口。

## 范围与类型

- 以指定功能及必要的测试/mock、调用方和类型依赖为单位，用 `git mv` 重命名，不全库改 import 或重构无关业务。
- JS 依赖及显式 `.js/.jsx` import 不是自动停止条件；检查当前 tsconfig、模块解析和调用契约，解决实际问题。需要扩大未授权范围或改变业务行为时才报告边界。
- 优先复用 `@superset-ui/core`、`@superset-ui/chart-controls` 及域内类型；私有类型就近定义，实际共享才上移。不为单次使用新建 helper 或公共类型层。
- 用 `Pick`、`Omit`、`Partial` 或继承表达真实关系；如实保留调用方输入、null/undefined 和返回契约，不把字段全部可选化或用 `any`/断言掩盖错误。React 状态、事件和 Redux props 沿用已有类型。
- 未知外部数据以 `unknown` 在入口校验并收窄一次，内部按类型流转，不新增重复运行校验或无必要的异常包装。mock 使用最小且类型正确的数据，必要断言说明保证来源。
- PropTypes 是运行时行为；仅确认当前 Babel 构建生成等价校验后才删除手写版本，类型文件或未使用的 validator 函数不构成兼容证明。保留 license 及必要接口说明。

## 验证与交付

- 读取当前 `superset-frontend/package.json`、tsconfig 和测试配置，使用已安装命令；不假定 wrapper 可用或自动下载未知工具。
- 同步相关测试和 mock，验证行为及真实兼容风险，不只测 import；纯类型声明无需虚构运行测试。共享类型或公共入口变化覆盖调用方和适用的项目级类型检查，不以单文件检查代替整体结论。
- 类型错误先查真实用法，再修类型或调用方，区分本次错误与原有基线；执行适用 lint/pre-commit 并检查自动修正；涉及外部副作用的测试核实隔离，仅实际影响、CI 要求或具体失败证据触发扩大检查。
- 按授权完成修改、验证、修复及交付，简述实际结果和未完成项；不预填 PASS，不强制报告模板，不在初版转换后停止。
