## Jinja 虚拟数据集点选兼容

单一 `from_expr/to_expr` 不能表示不连续区间。需要在窗口聚合前过滤的数据集使用
`WHERE {{ get_time_filter('snapshot_month', as_predicate=True, remove_filter=True) }}`。
该模式返回按数据库方言编译的完整区间并集；空数组恒假，非法区间拒绝。
点选仍保留外层精确过滤，连续模式沿用原有 `remove_filter` 行为。
旧宏遇到数组明确报错，不允许把包络误当成已选区间。

## 已确认行为

- 两个互斥按钮：连续区间、点选区间。历史配置未保存模式时默认连续区间。
- 连续模式保持现有起止点选择、时间比较行为。
- 点选模式点击一个日期单位选中，再次点击同一单位取消；支持跨年、不连续选择。
- 单位沿用按天、周、月、季、年、财年；不修改既有周起点、财季和财年边界。
- 图表与下游筛选器必须按选中区间的并集过滤，中间未选日期不得出现。
- 选中的单位按日期排序，不按点击顺序排序。
- 只选 A：没有上一选中区间；选 A/B/C：B 对比 A，C 对比 B。
- UI 标注“较上一选中区间”，不能继续标作自然时间环比。
- 变化率为 `(本区间值 - 上一选中区间值) / 上一选中区间值`；基期为 0 时显示“—”。
- 无时间轴图表（饼图、总计卡）按全部选中范围并集合计，不做相邻期比较；比较沿用图表已有的值/差额/变化率展示配置，不给原本无比较能力的插件新增展示模式。
- 切换模式保留选择；点选有空档时切回连续，需要先确认将包含中间日期；取消确认不得修改查询。

## 已核对的真实调用链与风险

1. `CustomTimeFilterPlugin.applyFilter` 目前发单个字符串 `time_range` 和绑定列上的单个 `TEMPORAL_RANGE`，比较值是 `1 week ago` 等固定偏移。
2. `nativeFilterDependencies.readMaskRange` 把多个不同范围判成 conflict；其 scope 和逐父级 hydrate 契约必须保留。不能直接把多区间传给现有函数而期待它自动工作。
3. `cascadeFilterOptions.getPayload` 仅传单个 `time_range`；普通图表 fallback 也需要保留完整并集，不能只带最早到最晚的包络。
4. `GetCascadeFilterOptionsCommand._build_statement` 为每个维度 UNION 子查询附加时间条件。并集必须整体括号包围后再 AND 父维度和 RLS，禁止改变 OR/AND 优先级。
5. `ExploreMixin.get_sqla_query` 目前仅接受字符串型 `TEMPORAL_RANGE`，多个独立条件是 AND，不是用户需要的 OR。
6. `ExploreMixin.processing_time_offsets` 通过固定偏移或指定范围执行比较查询；不支持每一个选中区间拥有不同的基期，不能把 B/A 的偏移直接复用于 C/B。
7. `getDashboardChartControls` 的关闭比较行为优先级必须保留；点选不能重新打开用户关闭的时间比较。

## 实施前需落实的边界

- 明确同一日期字段上有多个时间父级时的并集/冲突表示，不能仅比较包络字符串。
- 明确取消最后一个点选单位的状态：不得触发全历史请求。
- 若 B 没有数据，C 的基期仍应为 B，不能因数据行缺失而自动跳回 A；对无数据值的展示沿用缺失值处理，不伪造零值。
- 不同维度系列分别比较，不能将一个店铺/竞对的值移到另一个系列。
- 保留每个选中单位的身份；即使相邻单位在 SQL 中可合并过滤，也不能合并掉其比较边界。
